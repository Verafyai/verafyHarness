§ 1The validator

One model, wrapped in everything a validator does

On today's chains a validator re-runs code and votes on blocks. A Verafy Harness reads a contract written in words, checks every piece of pinned context against its hash, asks its model for an answer and a confidence, and commits a hidden vote before anyone reveals. The model brings judgment. The harness does the rest.

A harness commits to one model. Swapping the AI means changing the provider and model id, nothing else. Any open-weight model from Hugging Face will do. The network requires that every jury spans several model families and operators, and that every harness posts a bond it can lose.

§ 3Routing agent

The routing agent holds the keys and pays for the AI

A harness gets paid in whatever token a contract offers, and it has bills in other tokens: model APIs, GPU hosts, provers. The routing agent closes that gap on its own, within limits the operator sets.

Keyblock

Holds every API key and wallet key encrypted, and issues short-lived scoped keys. Nothing outside the keyblock holds a raw secret.

built

Banker

Accepts any token, swaps between tokens at the best approved quote, and funds each payment in the payee's token.

built, test venues

API router

Plugs into AI APIs, API routers, provers and cloud hosts, meters each call, and sends each contract only to AI that meets its provability level.

built, test APIs

Payment wallet

Where earnings land and bills are paid from, inside an allowlist and spending caps. It never touches the bond.

built

§ 5Quick start

Seal a block on your own machine

Needs Node 22 or later. The core has no dependencies. The demo uses scripted answers, so it needs no key.

git clone https://github.com/Verafyai/verafyHarness.git
cd verafyHarness
npm test          # 167 tests
npm run demo      # five contracts, five rulings, five blocks

With real models through any OpenAI-compatible endpoint (OpenRouter by default), keep the key in your environment and never commit it:

export VERAFY_API_KEY=...
node bin/verafy.js doctor --live
node bin/verafy.js run examples/market-resolution.json --live

Machine specs, acceptable models, costs, earnings and the full setup are in Run a harness.

§ 6Plugins

Run it from your favorite agent

Verafy Harness ships as an MCP server with a plugin for each major agent. Your agent can draft a contract in words, check it, pin its sources and run a jury, then read the ruling and the sealed block. Your agent is the client. The jurors stay inside the harness, where their tools are locked.

npx -y @verafy/mcpverified

Live calls are off until you turn them on and set a spend cap. Keys stay in your environment or the keyblock; no tool ever returns one.

§ 7Built on

Runs inside DeepSeek Harness

DeepSeek Harness is an MIT-licensed agent harness where everything is a plugin. Verafy Harness pins it as a submodule, leaves the upstream tree unmodified, and adds juror mode as a plugin.

Two tools, no others

A juror can load and check a contract, and cast a vote. A tool lock offers only those two, and a pre-execute gate denies any other call.

Context is evidence

Nothing a juror reads is treated as an instruction. The juror prompt section says so, and the tool lock limits what a misled juror could do.

Any open-weight model

DeepSeek Harness routes to a self-hosted server or any OpenAI-compatible gateway that serves open weights.
